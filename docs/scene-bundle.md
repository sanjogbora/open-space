# Scene Bundle Format

Published scenes are static bundles that can be hosted by the product CDN, embedded in a client site, or exported for self-hosting.

## Current Bundle

The first bundle lives at:

```txt
apps/viewer-demo/public/scenes/demo/
```

Files:

- `scene.manifest.json`: scene metadata, views, interactions, navigation, branding, and quality profiles.
- `scene.glb`: generated demo model used by the viewer.
- `scene.graph.json`: extracted object/material graph used by the Studio editor.
- `materials.json`: editable material override document applied by the viewer at runtime.
- `objects.json`: editable object visibility document applied by the viewer at runtime.
- `controls.json`: editable movement/control document applied by the viewer at runtime.
- `stats.json`: analyzer output with size, asset, mesh, material, and triangle counts.
- `optimization.json`: generated mobile/balanced/desktop budget report and recommendations.
- `embed.html`: standalone iframe embed example.

The manifest can be opened by the viewer with:

```txt
/?scene=/scenes/demo/scene.manifest.json
```

Embed mode uses:

```txt
/?scene=/scenes/demo/scene.manifest.json&embed=1
```

## Embed Script

The prototype embed loader is:

```txt
/embed.js
```

Usage:

```html
<script
  src="https://example.com/embed.js"
  data-scene="/scenes/demo/scene.manifest.json"
  data-title="Demo Residence Walkthrough"
  data-height="640px"
></script>
```

The script inserts an iframe pointed at the hosted viewer. This keeps the viewer isolated from the client page and gives us a stable path for fullscreen, autoplay, and future runtime messaging.

## Static Deployment

Published versions include `deployment.json`, which can be validated and copied with:

```txt
node scripts/deploy-published-bundle.mjs apps/viewer-demo/public/published/<project>/<version>/deployment.json --out=dist/published --dry-run
```

For production/self-hosting, pass both public URLs so the exported folder gets a launch page and embed example that point at the hosted viewer app and the deployed scene assets:

```txt
node scripts/deploy-published-bundle.mjs apps/viewer-demo/public/published/<project>/<version>/deployment.json --out=dist/published --viewer-base=https://viewer.example.com --public-base=https://cdn.example.com/open-space/<version>/
```

- `--viewer-base` is the hosted viewer application origin.
- `--public-base` is the final public URL of the deployed scene folder.
- The deploy script blocks bundles whose saved `qualityGate` is `blocked`; use `--allow-blocked` only for internal testing deployments.
- Add `--fail-on-warning` for client-ready validation that fails on saved quality-gate warnings, and add `--fail-on-deployment-warning` to also fail missing launch/cache/deployment checks.
- The deploy script writes `_headers`, `vercel.json`, `index.html`, `embed.html`, and `deploy-report.json` for static hosts.

## Manifest Rules

- `schemaVersion` must be `0.1`.
- `sceneUrl` is optional. If missing, the viewer uses its procedural demo fallback.
- Relative asset paths are resolved relative to the manifest URL.
- `views` define walk/orbit/top camera states.
- `interactions` define hotspots, links, video textures, material variants, and object toggles.
- `material-variant` interactions can target a mesh or material and expose color finish buttons in the viewer.
- `object-toggle` interactions can target an object by generated object id and stable object name.
- `objects.json` entries can set `hideInTopView` to hide ceilings, roofs, or helper covers only while a top/floor-plan view is active.
- `objects.json` entries can set `navigationBehavior` to `walk`, `collision`, or `ignore` when automatic floor/wall detection needs an explicit object-level override.
- `navigation.bounds` drives the viewer minimap scale when present.
- `navigation` defines camera height, floor mesh naming, collision mesh naming, and optional movement bounds.
- `qualityProfiles` define runtime pixel ratio, shadow, and antialiasing settings.
